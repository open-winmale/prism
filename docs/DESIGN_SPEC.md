# UI/UX 设计规格 · 白酒体检报告

> 版本 v1.0 ｜ 2026-10-21 ｜ 适用：M1 及后续所有 UI 改动
> 本文件是**还原度的标尺**：任何 UI 改动先对照本规格，再进入走查清单（§10）。与规格冲突的以本文件为准，改动规格需同步更新本文件。

---

## 1. 设计原则

1. **结论优先**：一屏之内先给判定（安全/关注/高危），证据在下。用户不为"看数字"而来。
2. **每个断言都有出处**：凡是有结论的地方，必须能看到支撑数字或"数据缺失"说明。看不到出处的结论不允许展示。
3. **窄屏不丢信息**：移动端只做重排，不做隐藏。佐证、单位、口径在 375px 下必须仍可见。
4. **一屏一问**：每个区块只回答一个问题，区块标题即问题。
5. **克制**：不使用渐变、阴影堆叠、装饰图形；用留白与色阶区分层级。

## 3. 布局规格

### 3.1 页面框架
- Header：sticky，高 56px，白色 90% + backdrop-blur，底边 1px `--wm-line`；左品牌 + 右导航（首页 / 关于 / 专业版 CTA）。
- Main：`max-w-6xl px-4 py-6`。
- Footer：1px 上边线，12px 灰色居中免责声明。

### 3.2 首页（改造后）
```
H1 一句话定位（白酒）
副标题：用一份财报，看懂一家白酒公司
[公司卡片网格]（每张：公司名 / 代码 / 香型·价格带标签 / 一句话特征）
[方法论说明入口]
[CTA：连接真实数据]
```
不再出现"选择行业"步骤（行业固定白酒）。

### 3.3 分析页（改造后）
```
[章节锚点条] 画像 · 排雷 · 增长 · 质地 · 结论   ← problem 参数决定默认锚点
[公司条] 公司名/代码 · 期间 · 数据来源标签（真实/示例）· 公司切换
[A 画像与判定]  [B 排雷清单]  [C 增长拆解]  [D 生意质地]  [E 结论与下一步 + CTA]
```

## 4. 组件规格

### 4.1 公司条
- 结构：左（名称 16px/500 + 代码·期间·香型 12px 次要）；右（公司切换 select，8px 圆角，1px 描边）。
- 数据来源标签：**真实数据**= emerald 浅底；**示例数据**= amber 浅底（当前是灰色小标，辨识度不足，必须强化）。
- 窄屏：纵向堆叠，select 占满宽度。

### 4.2 章节锚点条
- 横向 chip 组，高 32px，8px 圆角，间距 8px；选中态 `brandsoft` 底 + brand 文字；未选 slate。
- 点击滚动到对应区块（非路由跳转，保持单页报告）。
- 窄屏：横向滚动（`overflow-x-auto`），不换行。

### 4.3 Verdict 头（Zone A）
- 桌面：三列横排 —— ① verdict 徽章（全圆角，白字，安全绿/关注琥珀/高危红，高 32px）② 体检分环（112×112，环宽 12px，中心数字 24px + 等级 12px）③ 一句话结论（14px/1.6，`flex-1`，最小宽 160px）。
- 数据缺失提示：12px `--wm-slate`，写明「N 项检查因数据不足未执行」。
- 窄屏（<640px）：竖排堆叠 —— 徽章与环同一行居中，结论整宽在下；环缩至 96×96。

### 4.4 排雷清单行（Zone B）
- 行结构：`状态灯 24px | 检查名 | 佐证 | 等级标签 | 展开箭头`，行高内边距 12px，行间 1px `--wm-line` 分隔，hover 底 `#f8fafc`。
- **佐证列不得因窄屏隐藏**（当前 `hidden sm:block` 属信息丢失，必须修）：窄屏改为名称下方换行显示，12px `--wm-slate`。
- 检查名宽度：桌面 `w-56`（224px）→ 改为 `max-w-[14rem] truncate`；窄屏不限宽、允许换行。
- 状态灯：`✓` 安全绿 / `△` 关注琥珀 / `✗` 高危红 / `—` 缺失灰。
- 展开面板（浅底 `#f8fafc`，内边距 20px）：
  1. 「为什么危险 / 为什么安全 / 数据缺口」—— 14px 正文
  2. 「下一步核查」—— blue-50 底，14px
  3. 「老唐视角」—— amber-50 底，14px
  4. 证据图（有则显示，无则不占位）
- 同时只允许展开一行（当前行为，保留）。

### 4.5 体检分条（Zone C）
- 每行：`维度名 | 当前值 | 进度条 | 分数 | 权重`。
- 桌面：`grid-cols-[8rem_4rem_1fr_3.5rem_2.5rem]`，gap 12px。
- 窄屏：`grid-cols-[1fr_auto]` 两行：第一行 名称 + 分数，第二行 进度条（满宽）；权重与当前值合并进名称行 12px 次要文字。
- 进度条高 8px，圆角满；≥80 绿 / 30–79 品牌色 / <30 红。
- **维度为 na 时**：显示为灰色斜线底 + 「无数据」标签，且**该维度权重从分母剔除**（不得按 0 分计入）。

### 4.6 结论段（Zone E）
- 14px/1.6 正文，先给结论句，再给「该查哪条附注」清单（有序列表）。
- 段落后紧跟情境化 CTA（全宽卡片，brandsoft 底，按钮全圆角）。

### 4.7 CTA
- 文案模板：「用真实数据看 {公司名} 的完整专业版体检」；链接统一带 `utm_source=report-lens&utm_medium=github`。
- 位置：① Header 常驻 ② 侧栏 ③ **报告结论段后**（新增，转化意愿最强处）。

### 4.8 术语提示（新增 `TermTip.vue`）
- 触发：术语文字下 1px 虚线下划线 + `?` 图标（12px）。
- 浮层：白底，1px 描边，8px 圆角，内边距 12px，最大宽 280px，正文 12px；窄屏改为点击展开在下方（不用 hover）。
- 首批术语：合同负债、收现比、吨价、产销率、扣非净利润、权益乘数、基酒。

### 4.9 卡片容器
- 统一：白底 + 1px `--wm-line` + 12px 圆角 + `shadow-sm` + 内边距 20px。
- 卡片标题 16px/500，副说明 12px `--wm-slate`，标题与内容间距 4px。

## 5. 图表规格

| 项 | 规格 |
| --- | --- |
| 高度 | 桌面 288px；<640px 240px |
| grid | left 52 / right 18 / top 36 / bottom 52 |
| legend | bottom 0，`type:'scroll'` |
| tooltip | `trigger:'axis'`（饼图 `trigger:'item'`） |
| yAxis | `name = spec.unit`，置于轴顶 |
| 配色 | 注入 §2.1 序列色；增速类用涨跌色并在副标题注明 |
| 折线 | `smooth:true`，面积图按需 |
| 空数据 | **显示「该指标无数据」占位文字，不允许渲染空白画布** |
| 横轴标签 | `interval:0` 全显示；年份 ≤5 期不旋转 |

## 6. 状态规格

| 状态 | 表现 |
| --- | --- |
| 加载 | 骨架或「加载中…」12px 灰色，占位高度与内容一致，避免跳动 |
| 空 / 无数据 | 12px 灰色说明 + 灰斜线底；**禁止显示 0 或"通过"** |
| 数据缺失（na） | 灰 `—` + 「因缺少 X 字段未执行」，并提示连接专业版可补全 |
| 错误 | red-50 底，14px，说明失败原因与重试方式 |
| 禁用 | opacity 50%，不改色 |

## 8. 文案与语气

- 结论用完整句子，不堆关键词；数字与单位之间不留空格（如「240 亿」「91.2%」）。
- 单位统一「亿元」「%」「元/吨」「万吨」，全文禁止混用（如 RMB bn）。
- 涉及判断必须带限定词（「可能」「需核查」），禁止绝对化结论（「必然造假」）。
- 不做买卖时点与仓位建议；估值只给口径与区间，不给目标价。
- 所有真实数据展示处保留「不构成投资建议」与数据来源标注。

---

## 9. 可访问性基线

- 语义色不单独承载信息：状态灯必须同时有字符（✓/△/✗/—）。
- 交互元素最小点击区 32×32。
- 图表 `<div>` 加 `aria-label` 简述图表内容。
- 正文与背景对比度 ≥4.5:1（辅助文字 12px 亦需满足）。
