# 图表系统设计（v1.2）

> 目标：让图表回答「比较」而不是只展示「一条线」；所有改动 0 新增 EC。
> 实现入口：`src/features/charts/option.ts`（ChartSpec → ECharts option）与 `src/features/charts/EChart.vue`（运行时）。
> 开发预览：`npm run dev` 后访问 `/_chart-preview`（仅 dev 路由，不进生产包）。

## 1. 现状审计（2026-10-22）

| 问题 | 证据 | 后果 | 修复 |
| --- | --- | --- | --- |
| 参考线全部失效 | `EChart.vue` 产出 `markLine`，但 `echarts.use()` 未注册 `MarkLineComponent` | Beneish 门线、CFO/净利 100%、同业中位数、零线一条都看不见 | 注册 `MarkLineComponent` + `AxisPointerComponent` |
| 单指标是默认值 | 多数模块只传 1 条序列；概览 3/4 张图单线 | 用户看不到利润与现金、增速与规模的背离 | 概览 2×2 改为 2–3 序列；新增三表任选指标对比 |
| 行业对比只有一张写死散点 | `peersScatter` 写死 PE/ROE，tooltip 也写死 | 无法换指标；三表横截面只有表格 | 散点 X/Y 可换轴；新增分位图与关键指标小倍数 |
| 坐标系错误 | 存货「周转率(次)」与「周转天数(天)」共用一根 Y 轴 | 两条线量纲不同，读数无意义 | 左轴次数、右轴天数 |
| 交互与自适应缺失 | 无 crosshair、tooltip 无单位、单序列也显示图例、无 ResizeObserver | 图「呆板」、容器变化后画布不跟随 | 统一 tooltip/图例/轴样式；容器 ResizeObserver |
| 四方法只落地趋势 | `pieShare`/`stackedShares`/`commonSize*` 无调用方；横向只剩散点 | 结构/横向对比缺失 | 补横向柱、分位图、对比小倍数 |

## 2. 设计原则

1. **一图一问，优先对比**：每张图回答一个比较关系——时间对比、指标对比、同业对比；标题即问题。
2. **同轴同单位**：量纲不同必须双轴，或统一「基期=100」；绝不再把「次 / 天 / 倍」塞进一根轴。
3. **阈值与中位数必须可见**：参考线分三类语义——门线（琥珀）、中位数/基准（灰）、零线（浅灰）。
4. **缺失 ≠ 0**：null 传播到图；空图显示文字占位；不为了「好看」补 0。
5. **0 新增 EC**：图表只消费已有 `ctx` / `card` / `peers` / `compareTargets`；任何新取数必须先确认。
6. **引擎纯净**：`src/engine` 只产出 `ChartSpec`，不 import vue/echarts；ECharts 翻译集中在 `features/charts`。
7. **克制的视觉**：研究备忘录，不是仪表盘。细虚线网格、无阴影、字号 ≥11px、不用 emoji。

## 3. ChartSpec 语汇

```ts
type ChartType =
  | 'line' | 'bar' | 'horizontalBar' | 'pie' | 'scatter'
  | 'stackedBar' | 'groupedBar' | 'waterfall' | 'heatmap' | 'table';

interface ChartRefLine {
  value: number;
  label?: string;
  axis?: 'x' | 'y';
  kind?: 'threshold' | 'median' | 'zero';   // 门线 / 中位数 / 零线
}

interface ChartSeries {
  name: string;
  data: (number | null)[];
  as?: 'bar' | 'line';       // 柱线混排
  axis?: 'left' | 'right';   // 双轴
  area?: boolean;
  color?: string;
  dashed?: boolean;
  benchmark?: boolean;       // 同业基准：灰虚线，关闭面积填充
  unit?: string;             // 双轴时逐序列单位
}

interface ChartSpec {
  // ...既有字段
  yFormat?: 'number' | 'percent' | 'ratio';
  yFormatRight?: 'number' | 'percent' | 'ratio';
  highlightIndex?: number;   // 横条图高亮「本公司」
  legend?: boolean;          // 缺省多序列才显示
  note?: string;             // ChartFrame 脚注如实渲染
}
```

## 4. 渲染规范

| 项 | 规格 |

| 轴名 | 11px `#94a3b8`；散点轴名放轴中点 |

| 序列色 | `#1d4ed8` / `#0f766e` / `#b45309` / `#b91c1c` / `#6d28d9` / `#0891b2` |
| 门线 | 琥珀 `#b45309`、1px 虚线、末端标签白底；两条门线挨近时标签上下错开 |
| 中位数/基准 | 灰 `#94a3b8`、1px 虚线；横条图里隐藏标签，避免与末端数值打架（脚注仍列出） |

| 高亮 | `highlightIndex`：本公司品牌蓝，同业 `#cbd5e1` |
| 高度 | 小倍数 180px；自选对比 300px；同业散点 240–300px；关键指标小图 160px |
| 响应式 | ≤900px 2×2 变单列；≤520px KPI 两列；图表容器 `ResizeObserver` |

| 层 | 内容 | 说明 |

### 5.2 口径与呈现

| 所选单位 | 默认口径 | 轴 | 图形 |
| --- | --- | --- | --- |
| 1 种（如 3 个货币指标） | 原值 | 单轴 | 货币→柱状；百分比/比率→线形 |
| 2 种（如 营收亿元 + 毛利率%） | 原值 | 左轴第一种单位、右轴第二种单位 | 线形（可切柱状） |
| ≥3 种 | 基期=100 | 单轴 | 线形 |

- **指数不是百分比**：指数模式标题为「基期=100（非原值）」，单位标「基期=100」，序列 tooltip 单位标「指数」。茅台毛利率 91.3% 在原值模式显示 91.3；指数模式 2021 年显示 100（基期），不是毛利率变成 100%。
- 自动默认只在用户未手动切换时生效；手动选过模式/图形后保持，只有「原值 + ≥3 单位」失效时才强制切回指数。
- 原值双轴最多 2 种单位；3 种以上不硬塞多轴，统一走指数。
- 图形可手动切「线形 / 柱状」；原值 + 只有货币时默认柱状，其余默认线形。

## 6. 行业对比的数据边界

- **估值横截面**（PE/PB/PS/ROE/市值）：`members` 接口一次取回，0 额外 EC；可换轴散点、分位图、自身 vs 行业分位都基于它。
- **经营指标横截面**（毛利率/净利率/收现比/负债率/存货占比）：没有「行业平均时间序列」接口，只能对用户显式勾选并确认加载的同行三表做横截面；每家约 3 万 EC（24h 缓存命中为 0）。
- **不做全行业三表**：申万 L3 全成分逐家取三表约 63 万 EC，超出项目边界。
- **口径必须标注**：横截面分位 ≠ 自身历史分位；未对齐年份必须显示「未对齐（结论要打折）」；缺失不进中位数、不占排名。

## 7. EC 账

本批图表改造 **0 新增 EC**：

- 概览 2×2、自选对比、质量/风险/财报图表：全部基于当前 `ctx` 本地计算。
- 同业散点/分位、估值分位：基于已经随 `getDataset` 返回的 `peers`（members，约 3.4k EC/24h，原本就有）。
- `/compare` 关键指标：只在用户勾选同行并确认取数后出现；默认 0 家 = 0 EC。
- 图表模块不调用 `provider`、不触发新请求。

## 8. 验收

1. `npm run typecheck && npm run lint && npm test -- --run && npm run build` 全绿。
2. 单元测试覆盖：参考线三种语义、图例单/多序列、横向柱轴顺序、`highlightIndex`、tooltip 单位/缺失、基期=100、负基期留空、季度同季同比、行业对齐/缺失排除/中位数。
3. E2E：140/140（含概览三表任选选择器、双轴/原值/非原值指数、财报三表默认深挖、`/compare` 关键指标对照出图）；三视口基线重生成。
4. 三视口（1440/768/375）无横向溢出；2×2 在移动端单列；标签不重叠。
5. `grep -r "echarts" src/engine` 为空；图表模块无新增取数调用。
6. `dist` 不含明文体验密钥（沿用上一批的 XOR+Base64 方案）。

## 9. 已知限制

- ECharts 因新增 `MarkLineComponent`/`AxisPointerComponent`，gzip 约 +21KB；换来的是门线与十字准星这类核心证据能力。
- ECharts 的 markLine 标签在数值轴上的定位不完全可控：横条图的中位数标签已主动隐藏，改由图表脚注列出；门线标签仍保留。
- 行业经营指标仍只有横截面，没有时间序列；这是数据源边界，不是图表层能补的。
- 自选对比只覆盖 prism schema 的 `STMT_TREE`（42 行，去重后 37 个三表科目）；winmale-v2 专业版有 412 个 code，含 F10/附注/市场变体，prism 没有这些数据域。
- 双轴最多 2 种单位；3 种以上统一指数，不硬塞三轴/四轴。
- 专业版科目透镜是 1080×680 弹层 + 对比公司 + 无限同看；prism 保持工作台内联 + 最多 4 条线 + 单公司，避免仪表盘化。
- 开发预览路由 `/_chart-preview` 只在 `import.meta.env.DEV` 下挂载，生产构建不包含。
