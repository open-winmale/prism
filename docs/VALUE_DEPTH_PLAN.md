## 0. TL;DR

**综合评分 7.1 / 10**（v0.5.0 为 5.2）。

v1.0 重做把**产品形态**修好了（七工作区、结论先行、口径诚实），但**分析深度被 IA 清理切掉了一半**：

1. **引擎有 16 个分析模块，工作台只挂了 6 个。** 旧 IA（AnalysisPage/ModuleResult）在 Phase 5 被删，10 个模块从此没有 UI 入口——包括现金流八型、六维体检分、杜邦、产销量、附注。这是**纯浪费**，不是能力不足。
2. **现金流量表共同比的分母用错了**（用经营现金流净额当整表分母），在 CFO 为负的公司上直接产生负百分比，语义崩塌。
3. **暴雷预警停在「财务安全」层，没有进入「造假侦测」层**。Beneish M-Score 缺失——而**专业版也没有**，这是开源版能做差异化的地方。
4. **同业深度卡在 EC 而不是算法**：估值横截面（PE/PB/PS/ROE/市值）已经能拿（`members` 接口，0 额外 EC），三表经营指标（毛利率/净利率/收现比）的分位拿不到，因为要 21 家 × 3 万 EC = 63 万 EC。

**方案核心：前两批次全部 0 新增 EC。** 深度提升的来源是「把已有引擎资产挂回 UI」+「移植专业版真源里纯三表可算的公式」，不是加数据源。这完美契合「成本可见、能在已有数据上算的绝不重新拉数」。

## 1. 调研结论：深度边界（哪些能做，哪些不能）

### 1.1 专业版独占，开源版不碰（数据源卡死，不是算法问题）

| 能力 | 卡点证据 |
| --- | --- |
| 盈利预测 / 一致预期 | `script/sys/forecast/const.xs:4-6` 数据源 `alt.bssaa` + `cn.yjyg.PROPS` |
| 股东股权 / 机构持仓 / 沪港通 / 国家队 | `winmale-v2/src/features/analysis/pages/shareholder/`、`institution/` |
| 公告 / 并购重组 / 处罚诉讼 / 股权质押 | `winmale-v2/src/features/filings/`、`script/sys/filings/init.xs:6` |
| 个股提醒 / 实时推送 | `winmale-v2/src/api/realtimeAlertWs.ts`、`script/sys/alert.xs` |
| 实时行情 / K 线 / 资金流 | `script/sys/kline/manifest.json`、`sys/moneyflow/init.xs:7` |
| F10 年报原文穿透 | `script/assets/deepread/cn/`（40 个标的硬编码） |
| **附注 / 分部报告 / 量价** | **21 个 rptdom 域均非三表**（`script/sys/rptdom/const.xs:10-32`：`notes.inventory`、`notes.expense_detail`、`ops.product_revenue`） |
| **申万 L3 行业分位** | 分母是**行业内全部成分股的横截面值**（`script/sys/metric/screen.xs:232-237`，6 项全为 `PERCENTILE($INDUSTRY_CUR, <指标>)`） |

> **判定**：附注穿透与申万 L3 分位**门槛在数据源，不在算法**。`PERCENTILE` 本身只是排序取分位（纯计算，可复现），但需要「申万 L3 成分股列表 + 各成分股同口径指标」两项三表之外的输入。
> 开源版 `members` 接口能提供**估值类横截面**（PE/PB/PS/ROE/市值），但**给不了三表经营指标的横截面**。这个边界必须在 UI 里说清楚，现在没说。

### 1.2 专业版有真源、开源版可直接移植（纯三表可算）

| 方法论 | 真源 | 可移植性 |
| --- | --- | --- |
| 三表共同比 | `script/assets/pages/lib/stmt_tree.xs:66-76`（`ratio(num, den)` 构造器）+ `:42-52`（`shareOf` 章节基数） | ✅ 纯三表比值，连市值都不需要 |
| 增长来源拆解 | `script/assets/cn/company/导览.这个生意如何.md:59-63` | ✅ 恒等式 `$STM = $SE + $TL + $MIN`（`sys/metric/begin.xs:154`），只用到 `PICK()` 与 `AR()` 两个时序算子 |

### 1.3 专业版也没有，需自研（差异化机会）

| 方法论 | 检索结论 |
| --- | --- |
| **Beneish M-Score** | **全仓 0 命中**。`Beneish\|M-Score\|MScore` 无结果；`DSRI\|GMI\|AQI\|SGI\|DEPI\|SGAI\|LVGI\|TATA` 无方法论命中（仅有科目名误命中）；`script/assets/cn/company/导览.疑点排雷.md` 只有 6 个空标题（`:9-19`，正文为零）；`assets/pages/cn/company/资产负债表/schema.xs:152` 仅展示 note |

> **结论**：Beneish 不是「不可做」，是「没得抄」——8 因子（DSRI/GMI/AQI/SGI/DEPI/SGAI/LVGI/TATA）全部可由**连续两年三表 + 营收 + 应收账款 + 折旧**算出，0 新增 EC，但阈值需自研自定。
> 且专业版**没有任何分位阈值判定代码**（`screen.xs:232-237` 只产出分位数值），移植时也无阈值可抄——这反而是开源版自己立标准的机会。

## 3. 问题清单（P0–P3）

### P0-1 · 现金流量表共同比分母用错

- **[src/engine/methods/columns.ts:61-66]**
- **problem**：`shareDenominator` 对整张现金流量表返回同一个分母 `net_cash_operating`（经营现金流净额），投资活动、筹资活动科目也用它当分母。
- **evidence**：
  - 专业版真源 `script/assets/pages/lib/stmt_tree.xs:367/399/416/432/438` 规定 CF 各段分母是**各段自己的现金流入小计**（`NFOI`/`NFII`/`NFFI`/`NCF`），只有「附注调节段」用 `NCFO`。
  - 制造排雷样本 2024 年 `net_cash_operating = -6 亿`、`capex_cash = 45 亿`（`src/data/samples/manufacturing.ts:108`），共同比列将算出 **−750%** 这种无意义值。
- **fix**：按 CF 分段取分母（经营段用流入小计、投资段用投资流入小计、筹资段用筹资流入小计）；流入小计缺失时该段占比置 `null` 并在表头脚注标注「共同比口径：各段 ÷ 该段现金流入小计」。禁止用 `net_cash_operating` 一把尺子量全表。

### P0-2 · 16 个引擎模块里 10 个零挂载

- **[src/features/workbench/*]**
- **problem**：Phase 5 删除旧 IA（`AnalysisPage`/`ModuleResult`/`ReportHero`）后，新工作台只直接调用 6 个模块（`mineChecks`、`profitDrivers`、`qualityModels`、`cashFlowQuality`、`cashConversionCycle`、`seasonality`），其余 10 个从此没有 UI 入口。
- **evidence**：全仓 grep（排除 `*.test.ts`）显示以下符号**仅出现在** `engine/index.ts` 导出与其自身定义处，**无任何 UI 调用点**：
  `runRoe`、`runGrossMargin`、`runNetProfit`、`runAssetStructure`、`runInventory`、`runFixedAssets`、`runProductionSales`、`runFootnote`、`runCashFlowType`、`runQualityCheck`
  这 10 个模块包含：现金流八型（`analysis/cashFlowType.ts:16-23` 八型编码表）、六维体检分（`analysis/qualityCheck.ts:74` `qualityScoreOf`）、杜邦分解（`roe.ts`）、产销量（`productionSales.ts`）、附注（`footnote.ts`）。
- **fix**：按「挂在哪个工作区」重新分配挂载点（见 Batch 1），用 `InsightList` 统一渲染，不新增组件。

### P0-3 · 估值页只有自身历史分位，缺行业横截面分位

- **[src/features/workbench/ValuationWorkspace.vue:85-102]**
- **problem**：估值页只画 PE/PB 的**自身 3 年历史分位**，`medians`（:17-22）只算行业中位数，**没有行业横截面分位条**。
- **evidence**：`rankOf` / `quantile` 已在 `engine/methods/peersChart.ts:34` / `:96` 实现并在 `PeerPanels` 使用，但 `ValuationWorkspace` 未引用；页面只消费 `card.pct_pe_3y` / `card.pct_pb_3y`。

### P1-1 · 造假侦测缺位（Beneish M-Score）

- **[src/engine/analysis/qualityModels.ts]**

### Batch 2 · 深度引擎（造假侦测 + 增长来源 + 结构诊断）—— **0 EC**

| # | 动作 | 口径 | 验收 |
| --- | --- | --- | --- |
| 2.1 | `beneishM()` 8 因子 | DSRI = (应收<sub>t</sub>/营收<sub>t</sub>) ÷ (应收<sub>t-1</sub>/营收<sub>t-1</sub>)；GMI = 毛利率<sub>t-1</sub> ÷ 毛利率<sub>t</sub>；AQI = [1−(流动资产+固定资产)/总资产]<sub>t</sub> ÷ 同口径<sub>t-1</sub>；SGI = 营收<sub>t</sub> ÷ 营收<sub>t-1</sub>；DEPI = 折旧率<sub>t-1</sub> ÷ 折旧率<sub>t</sub>；SGAI = 销售费用率<sub>t</sub> ÷ 销售费用率<sub>t-1</sub>；LVGI = 杠杆<sub>t</sub> ÷ 杠杆<sub>t-1</sub>；TATA = (净利润 − CFO) ÷ 总资产<br>M = −4.84 + 0.920·DSRI + 0.528·GMI + 0.404·AQI + 0.892·SGI + 0.115·DEPI − 0.172·SGAI + 4.679·TATA − 0.327·LVGI<br>**M > −2.22 → 疑似操纵嫌疑**；任一因子缺 → 该因子按 1（中性）代入并计入 `missing`，**missing ≥ 3 时整体置 `na`**<br>折旧率 = 折旧费用 ÷（折旧费用 + 固定资产净额） | 茅台/五粮液/泸州老窖三家均落在安全侧（M < −2.22）；制造样本落在操纵侧；单测覆盖「缺 ≥3 因子 → na」「缺 1-2 因子 → 计算并明示缺失」 |

### 8.1 本轮顺带修掉的口径问题（实测暴露，非原计划）

1. **现金流量表共同比分母**：改用「流量项 ÷ 营业总收入、期末现金 ÷ 总资产」，不再拿经营现金流净额当整表分母。
2. **现金流量表「现金净增加额」行**：此前直接取 `net_cash_operating`，与上一行 NCFO 完全重复；改为 `sum_all(经营+投资+筹资)`，缺任一项则 null。
3. **`yoy()` 基期为正的硬约束**：基期为 0 或负 → null。此前现金净增加额由 −20 亿变 +196 亿会算出「−1070.7%」，没有任何解释力。
4. **异动扫描的单位**：比率行的「同比」用百分比、「结构位移」用百分点，此前混用会把「费用率涨 87%」写成「涨 87 个百分点」。
